## 普洱地形与路标

普洱行走继续使用`assets/cities/puer/map_data.json`中的简化碰撞，镜头使用独立层4的`camera_collision.res`。单城烘焙指令：

```sh
BAKE_CITY=puer /Applications/Godot.app/Contents/MacOS/Godot --headless --path game --script res://tools/BakeCityCollision.gd
```

镜头只纳入竹楼、门楼与奘房主要建筑，排除棕叶、茶山、地面和装饰，避免它们把镜头挤近。行走有四边实体边界与掉落安全恢复；没有水渠、桥或丽江水车，因此不机械复制那些阻挡。

简化地面是一大块碰撞，不能从地面shape名识别道路。`PuerWalkGuide.gd`先用共用`CityWalkGuide`做实体地面和人物空间采样，再仅对可走格按本城七条道路中心线加权。道路不是通行许可，权重不会解除房屋碰撞；金色箭头与小地图始终使用同一物理路径。小地图按本城bounds[-30.5,30.5,-21.5,21.5]归一化。

三位原地图人物位于`ACTOR_Hostess`、`ACTOR_TeaFarmer`和`ACTOR_NoviceMonk`。将其与对应锚点对齐，添加姓名和NPC碰撞，不另叠一个重复人物；岩香设在金塔南侧安全入口，室内叙事切换已有背景。

## 自动接续与领奖

核心正常完成后保存`flow/puer/yanxiang_visit`，由共用路由自动进入原小游戏。主线`script`带`defer_reward=true`，两关真实通过只保存`flow/puer/script`。小游戏直接回原地图，自动进入8句收尾，不再插入重复的誓约确认页或写着已领碎片的提前结算页。

收尾正常完成并核对全部条件后才调用幂等`collect_fragment()`，解锁古城。小游戏退出保留位置、yaw、pitch和距离；两关通过后收尾中断不重玩。旧完成档直接显示完成。独立mock与旧直接小游戏入口仍保留原来的誓约确认和独立结算流程。

重新检查所有小游戏自己的结算UI，不能只修改`PuzzleBase`。誓约为游戏创作，领取页与图鉴均明确其来源；现版六句有前后承接词，未回退早期规则文档的并列句子。两张医药类干扰叶改为不含具体服用方法的短句。

## 真实输入的坐标问题

自动化真实鼠标拖放发现：`Control.get_local_mouse_position()`可能与事件所在视口的位置缓存不一致，尤其在窗口缩放、无原生鼠标或内嵌视口时。拖动偏移现在由鼠标按下事件的位置计算，后续移动由事件视口坐标经根节点逆变换得到，不依赖原生光标缓存；拾回缩小的落叶也使用相同变换。

必须注入实际按下、移动、松开事件并核对最终六叶顺序，不把直接赋值`_order`当作拖放验收。说明页按钮也按真实控件中心点击，不手抄坐标。

原生窗口的容器布局需等渲染帧结算后再取点击中心。物理帧可能比渲染帧多，自动测试驾驶员同步yaw与玩家heading，并每物理帧重发W按下事件，防止外部窗口失焦清除测试按键。路径格距0.6米，测试路点到达容差0.28米；不直接改玩家位置来代替主线实走。地图中断提示使用现有深绿提示条样式，避免大面板纹样的最小高度溢出屏幕。

复核截图还发现快速拖放会中止贝叶入场渐显，使某些叶子一直半透明。拖起与归位时重设叶子alpha=1，测试除核对数组顺序外也核对六叶完整可见。读取城市时需等路由淡出后的自动对话创建完成，不能把路径ready当作叙事ready。小地图当前通过`NarrativeMinimap`薄封装入口复用`CityMinimap`。
