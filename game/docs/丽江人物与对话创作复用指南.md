# 丽江人物、3D与对话创作复用指南

整理日期：2026-10-11。用于香格里拉、大理、普洱等地图继续完善。先读本文件，再按需要读《城市地图接剧情复用经验》及本城经验；以当前主工程为准，旧候选只用于追溯测试。

本文件沉淀人物美术、五角色模型、双人物对话、手机互动与简短再次对话。本轮整理不修改游戏运行逻辑，也不表示其他地图已经完成这些升级。

## 直接交给其他地图聊天的指令

> 请先阅读 `game/docs/丽江人物与对话创作复用指南.md`、`game/docs/城市地图接剧情复用经验.md`、`素材/catalog/丽江人物与对话复用清单.json`，再检查本城已确定文案、地图和现有素材。沿用现有女主身份与剪影、阿东巴参考所建立的Q版NPC画风及共用对话排版，为本城已有NPC接入对应立绘与3D模型；不要将丽江人物冒充本城人物。对话左侧显示当前交谈NPC，右侧显示已有女主剪影；首次完成后再次交谈改成简短回应，退出初次对话不记完成。需要展示手机照片时复用手机外壳、亮度和放大机制，替换本城照片、触发位置与台词；不需要手机的对话保留人物舞台即可。保持本城站点、小游戏、碎片ID与已确定剧情。使用最新共用组件，逐城检查模型尺寸、朝向、落地、碰撞、地图站位和所有对话ID映射。保留修改前文件，做本城真实鼠标/行走/小游戏/收尾测试，冻结候选并独立验证，交付本城素材展示和测试记录。

## 2. 人物创作顺序：先看已有图，再生新图

这次最有用的修正是先看阿东巴实际PNG。仅凭「精致手绘」描述会生成接近正常成人比例的人物，与已有大头短身阿东巴不一致。后来直接引用阿东巴作为**画风参考**，才获得协调的三个NPC。

- 地图NPC延续圆润大头、短身、小手脚、暖色描线和手绘阴影；不要用女主正常比例服装设定页替代NPC画风参考。
- 女主的身份、低马尾、黑框眼镜与各站套装已有基准；模型保留身份特征，对话右侧仍复用之前出现的剪影。
- NPC用服装、发型、年龄和一个主要配件建立辨识：银饰大姐的发髻/银饰/酒红围裙，小学生的青绿衣/赭黄书包，客栈老板的赭色衣/围裙，阿东巴的白胡须/法冠/字卡。
- 生成单人物、完整头手脚、透明背景的竖向图，不生成姓名和UI文字。人物朝向轻微朝画面中间，给轮廓留余量。
- 同一批不同NPC分别生成，逐张检查。提示词、原PNG、参考关系和最后使用路径一起保存；未使用稿不混进图册的最终素材。
- 图像缩放、明暗、取样放在显示层；不因布局问题直接改掉原始透明图。

可改写的提示词结构：

```text
Reference role: existing Adongba portrait is STYLE reference only.
Create ONE new [本城NPC身份/年龄/表情].
Match its rounded storybook chibi proportions, warm fine ink outline,
textured hand-painted shading and restrained palette.
Keep [本城服装、发型、配件]. Full head, hands and feet visible.
Single centered full-body portrait, subtly facing toward the dialogue center.
Genuine transparent background; no scenery, captions, watermark or extra people.
```

这里的Q版是本项目地图NPC的局部一致性要求。不能据此把已确认的其他场景和女主身份设定全部重生。

## 3. 3D模型与地图接入

本次模型由本机Blender按参考图制作，使用真实立体网格、材料与分件节点，交付GLB、`.blend`、生成脚本和渲染图。不是把立绘贴在平面上当成3D，也没有使用付费图片转3D服务。

五个模型的部件数量分别为女主46、银饰大姐52、小学生42、客栈老板45、阿东巴83，详见 `models/model-info.json`。该记录统计原网格多边形，不能直接当成Godot最终绘制三角面数或性能保证。

### 模型必须约定的内容

| 项目 | 丽江实现 | 其他城市如何处理 |
|---|---|---|
| 格式与轴向 | 导出GLB、Y向上 | 检查Godot实际朝向和脚底位置，不只看Blender视图 |
| 来源与高度 | 普通模型按1.66、东巴按1.94归一化 | 为本城每个模型记录实测高度，不复制这两个数字 |
| 地图人物高度 | 女主1.65m；小学生1.2m；普通NPC1.65m；东巴显示1.75m | 跟本城人物设定、标签与原碰撞核对 |
| 视觉根节点 | `CharacterVisual` | 保留统一名字，便于替换与对话隐藏/恢复 |
| 可运动节点 | 名称包含 `Leg_L/Leg_R/Arm_L/Arm_R` | 使用步行动作时保留节点和正确关节原点 |
| 朝向 | 当前动作按模型正面+Z计算 | 新模型面向不同就改对应基准；检查实际移动 |
| 角色碰撞 | 由原城市角色与NPC碰撞承担 | 替换视觉模型不能删掉玩家碰撞、NPC碰撞或改坏任务半径 |

`CharacterMotion.gd`只给直接父节点是`CharacterBody3D`的模型做手脚摆动与朝向插值，当前NPC保持静态。它是轻量分件动作，没有完整骨骼、表情或动作库；任意外部模型不能只挂脚本就期待动作有效。

`LijiangCity.gd`里 `_character_model()`、`_build_player()`、`_build_hotspots()`展示了接入方法。保留原移动/碰撞，模型成功加载后再去掉直接的胶囊视觉。修改只进入本城类，不给所有城市强行换同一个人物。

NPC锚点、角色、路线终点、小地图标记和交互使用同一安全位置。阿东巴院门的 `(0,0,1.6)` 偏移属于丽江地形，不是通用坐标。要真实走到人物面前，检查脚底有地面、眼前没有墙、模型与标签不穿屋顶。

源`.blend`为五人合照场景，角色根节点有排版偏移；导出单角色前应恢复该角色根位置到原点并只选该角色层级。现有五个GLB是在合照排版前分别导出的。

Blender源脚本 `build_characters.py`含本机绝对ROOT、丽江输出名，并会清空当前场景。它是制作参考：在复制件上改ROOT/OUT/GALLERY与人物分支，使用空白后台Blender进程；直接运行原脚本会重新写丽江文件。

## 4. 双人物对话：人物舞台和正文分开

当前 `DialogueScene.gd`承载打字机、姓名卡、正文、选项、继续与结束信号。`LijiangDialogueStage.gd`承载左NPC、右女主、地图压暗和手机。不要为每座城复制一份旧对话脚本，覆盖主工程的新功能。

基本布局按1280×720设计，其他宽高和导出平台需要实际检查。丽江舞台坐标可供参考：左人物区域 `(50,106)/(340,336)`，右女主 `(905,126)/(330,312)`，手机区域从 `(440,108)`开始；底部正文与姓名卡仍由共用场景管理。

- 同一场交谈，NPC留在左侧，女主留在右侧。切换说话人只调整明暗，不每句话交换位置或把另一人清掉。
- 姓名卡跟随当前说话人，旁白仍有自己的卡。正文36字号、短句垂直居中、长句在既有区域内可读。
- 舞台置于正文UI后面；背景切换后也不能把人物舞台盖住。旧的单立绘控件在该舞台生效时隐藏。
- 对话时隐藏地图人物的视觉与姓名，避免地图3D女主和右侧剪影重复；只改可见性，不删除碰撞。正常完成、结束交谈和中断后都恢复。
- 图片及装饰用`MOUSE_FILTER_IGNORE`；滑杆与按钮正常接收GUI输入。图像不应挡住点击继续。

### 当前仍是丽江专用代码的部分

`DialogueScene._ready()`只识别 `LijiangDialogueStage.PORTRAITS` 中的对话ID。其他城市仅增加JSON的 `portrait` 字段，不会自动获得完整双人物舞台。

其他地图应选用本城舞台，或在目标改造批次中抽取配置驱动舞台。需要接入这些接口：`prepare(id)`、`show_line(index,speaker)`、`blocks_continue()`、`photo_ready`信号；并让共用对话选择正确舞台。本轮只提供接入说明与现有源码快照，没有悄悄新增通用舞台系统。

所有本城初次、核心、收尾、再次对话ID都要映射。只补初次ID会造成再次交谈立绘消失。不要把其他城ID映射到丽江人物只为让代码跑通。

## 5. 首次、再次、重试对话要有不同含义

当前 `NarrativeCity.interact()`已支持 `repeat`。街头NPC首次整段完成后，下一次选择 `item.repeat`；首次中断仍回初次完整对话。核心NPC的再次招呼在整站完成后走 `core.repeat`，不能因此绕过核心教学、小游戏重试或待核对收尾。

配置参考，只在本城现有配置中合并相应字段：

```json
{
  "id": "your_npc",
  "dialogue": "your_city_npc_first",
  "repeat": "your_city_npc_repeat"
}
```

`*_repeat.json`建议一句简短回应，仍有姓名和既有立绘，`on_end`使用本城现有的正确收尾方式。丽江四份再次对白在 `game/data/dialogues/lijiang_*_repeat.json`，可看格式，不复用它们的身份或地点台词。

进度只由正常完成初次交流记线索；再次、重试不重复加线索或奖励。没有读完就退出，不要设置首次完成标记。图册截图来自人物批次，尚未包含简短再次对话的窗口验收画面。

## 6. 手机：素材外壳、照片、操作与进度分别处理

手机正面由已有设备设定页派生为透明图，游戏用AtlasTexture取样，只合成实时照片。最早直接取样设定页会带米色底框，最终使用独立正面素材解决。

当前手机取样区域是1024×1536源图中的 `(183,129,652,1278)`，显示185×320；屏幕照片区是手机内 `(20,30)/(146,254)`。换设备图时重新核对取样与屏幕区域，否则照片会越过边框或遮住听筒。

亮度流程：35%开始 → 玩家改变滑杆 → 达到70%以上 → 点击「让阿东巴看照片」 → 解除继续门槛。照片变亮是图像显示调制，不调整操作系统亮度；放大2.5倍通过遮罩显示中央纹样，不改古锦原图。

当前以 `lijiang_dongba_visit` 的**零起算第6—14行**显示手机，第8行要求操作。若增删对白，不同步更新 `show_line()`，操作会落在错误台词上。其他城接入时应把对话ID、显示范围、必操作行、照片、人物名字和确认文案一起记录；多互动内容适合在相应开发批次改成显式事件配置。

继续函数先区分「补全文字」与「推进下一句」。必须操作且未确认时，正文继续不能跳过；GUI阶段接收滑杆/按钮的鼠标、方向键与确认键。确认信号只更新提示，不直接多跳一句。操作中退出后重新交谈，从未完成的首次流程重新开始。

没有手机剧情的本城舞台不需要创建/加载手机照片控件。迁移时尤其检查 `prepare()`是否无条件加载丽江图片，不能只把 `phone.visible`设成false就认为已解除依赖。

### 下一城实际验收

1. 窗口查看所有NPC与女主，模型正面/背面/脚底正确，标签、影子与碰撞位置一致。
2. 连续WASD到每个必访点；换大角色后仍能过门、上台阶、过桥。不能只传送测对话。
3. 初次、再次、核心、收尾、旁白都有正确姓名和图片；讲话人明暗一致；无文字、按钮或图片溢出。
4. 手机上实际点击/拖动/方向键，暗屏不能跳过，放大不推进，确认不多跳；退出恢复不偷记剧情。
5. 首次中断仍读初次全文；再次简短，重复计数不增加；小游戏与待收尾状态不能被短招呼挡住。
6. 真实完成本城小游戏和最终收尾，原ID保留，未收尾不领奖、已完成旧档不重复发奖。
7. 修改后再冻结、复制到独立目录运行，保留本城自己的日志、截图和指纹；不沿用丽江107项作为本城通过。
