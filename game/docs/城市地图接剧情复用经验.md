# 城市地图、剧情与小游戏复用指南

升级：2026-10-10。基于Godot 4.7.2主工程与丽江两轮实际试玩修正，供香格里拉、大理、普洱等城市同步。各城保留自己的故事、地图与小游戏。

本指南依次提供同步指令、文件适配表、丽江实测经验、迁移时的具体限制与验收清单。丽江与香格里拉已使用配置驱动的`NarrativeCity.gd`和`NarrativeMinimap.gd`复用剧情、探索与引导；香格里拉适配见[本城经验](香格里拉地图接剧情经验.md)。其他城市应按自己的数据与组件接入。

## 人物与对话升级补充（2026-10-11）

人物、五角色3D、左右立绘、手机亮度/放大、简短再次对话的最新交接，见[丽江人物与对话创作复用指南](丽江人物与对话创作复用指南.md)。可直接复用的女主剪影、手机、UI，以及需适配的城市人物、触发台词位置、模型高度，均有单独清单和交接包。下文较早的硬编码描述只作排障背景，当前共用流程以`NarrativeCity.gd`及相关最新组件为准。

## 直接同步给其他城市任务

复制以下内容，把方括号替换为目标城市与该城资料路径：

> 请依据主工程 `game/docs/城市地图接剧情复用经验.md`，将[城市名]升级到丽江最新体验标准。先读取[本城已确定故事及资料路径]、实际地图锚点和已有小游戏，保留站点、小游戏与碎片ID。落实斜俯视、鼠标直接转视角和Tab光标、金色方向箭头、小地图、人物旁E提示、旁白姓名卡、36字号居中文本、点击/空格继续。建立本城开场—沿途访谈—核心NPC—自动小游戏—自动收尾—碎片链路；中断不推进，返回保留位置与视角，收尾前不领奖。复用共用组件，逐城调整坐标、地形、碰撞、标记和条件，检查本城小游戏结算文案，不能只复制丽江硬编码。同步游戏说明，连续实走必访点和桥，真实完成小游戏及收尾，再测中断、自由顺序、暂停、存档与旧档。保留修改前副本，冻结并独立测试最终候选，记录证据和本城新经验。

### 同步后的体验标准

| 环节 | 应保持的体验 | 本城需要确定的内容 |
|---|---|---|
| 初次进入 | 自动旁白，显示「旁白」姓名卡，说明目标 | 开场文本、实际出生点、任务 |
| 探索 | 看清建筑正面和街道纵深；鼠标直接转视角 | 镜头方向、俯角、距离、FOV |
| 访谈 | 整段完成才记线索，重温不重复计数 | NPC数量、自由或指定顺序、线索 |
| 引路 | 金色箭头与小地图共用可步行路径 | 路网、地形高度、桥、边界 |
| 接近人物 | 人物旁E提示，隔墙不提示可互动 | 站位、半径、高差、前置条件 |
| 对话 | 旁白卡、36字号、短句居中、点击/空格继续 | 说话人、立绘、背景、选项 |
| 核心对话 | 正常读完直接进入本城小游戏 | 实际手艺模块及开始条件 |
| 返回与收尾 | 退出回原地点；通关自动接收尾；中断可恢复 | 标记、重试入口、收尾文本 |
| 奖励 | 收尾结束才发碎片，旧完成档不重复发奖 | 原有碎片ID与下一站 |

## 已实现的丽江链路

古城口旁白 → 银饰大姐／小学生／客栈老板（顺序自由） → 东巴院门外阿东巴 → 院内字卡辨认、马帮残页归序 → 阿东巴核对、交代丹增线索 → 东巴茶经碎片 → 解锁香格里拉。

出生自动播放旁白；三处访谈只在整段对话结束时记线索。结束交谈不记进度，可再次按 E。Tab显示光标后，访谈清单和小地图可点击切换引导目标，不自动移动。路面金色方向箭头与小地图路线由真实碰撞采样生成，草地可以走，但铺装面有更低寻路代价。进入小游戏后退出、通关均返回原位置和视角。收尾在通过小游戏后自动接入；收尾中断可恢复，不必重玩两关。

## 1. 先检查真实站位，再接对话

GLB Empty 是语义标记，不能当成已经验证过的角色脚底位置。丽江的 `GOAL_DongbaCourtGate` 位于院墙里面；直接挂 NPC 会造成看得见目标却无法靠近、隔墙互动。保留原 GLB，在 `LijiangCity._ready()` 将实际问话点向街道移动 `Vector3(0, 0, 1.6)`，NPC、交互半径、路线终点同步使用这个位置。院内叙事使用项目已有院景；没有新建可步行的 3D 室内。

每个点至少验证：脚底有地面、周围有一米以上的停留空间、从主路能连续走到、视线能到达 NPC。引擎转换以实际 GLB 为准；本项目大理旧 GLB 的 Empty 轴向需要单独修正，不能从丽江复制假设。

## 2. 行走碰撞与镜头碰撞分开

- 层 1：角色行走与交互视线用的地面、建筑、固定障碍、水渠安全阻挡。
- 层 2：玩家胶囊。
- 层 4：镜头建筑阻挡。

`BakeCityCollision.gd` 支持 `BAKE_CITY=lijiang`，不会重写其他城市的资源。丽江删除旧合批 NPC、树叶、目标色板和茶叶装饰的碰撞，保留主要建筑和实物陈设。薄地面仅取上表面，避免背面与台阶卡住。`CityCollisionData.names` 保留每个形状的来源名称，供路径代价与排障使用。

水面不是地面，也不能靠材质区分“能不能走”。`LijiangCity` 按水渠折线建立实体安全阻挡，在三处真实桥位留开口；高度超过角色正常跳跃。三座桥必须分别验证跨越，不能只测出生点。水车活动叶片用固定底座阻挡，避免每片叶片干扰走路。底座位置读取 `Waterwheel_axle.global_position`，不手抄带轴向正负号的坐标。

## 普洱本城适配补充（2026-10-10）

普洱已使用共用`NarrativeCity`、`CityWalkGuide`和数据驱动`CityMinimap`。普洱脚本只复用原地图三个人物、按本城道路加权和显示领奖页；无河道与桥。保留`puer/script/frag_beiye_oath`，通关自动接8句收尾后领奖。原生窗口实走和真实鼠标拖放发现的输入坐标、容器布局与测试按键失焦经验，见[普洱地图接剧情经验](普洱地图接剧情经验.md)。下文丽江实例中的硬编码描述是迁移前的背景，后续迁移应以当前共用组件和本城配置为准。

## 3. 镜头要覆盖体积，参数按城市配置

丽江默认 yaw=0.35、pitch=0.70 弧度（约40°，按用户截图调整）、距离12米、FOV=50。鼠标直接转视角、滚轮缩放，R恢复默认；Tab显示光标点击任务和小地图。俯仰限制0.38—0.95、距离7—16米。出生点在原入口锚点基础上偏移 `[3, 0, -5]`，移到水车旁开阔街面，避免后墙迫使镜头收成角色特写。主镜头方向与出生站位必须一起验画面，不能只改俯角数值。

用半径0.28米的球形扫掠代替单条射线，为镜头近裁剪面预留空间。只检测镜头层；河道安全阻挡、NPC和小装饰不应突然缩镜头。遇墙立即收近，恢复距离按时间平滑，避免帧率变化带来明显差异。出生点、广场、NPC门前与绕墙角分别检查，屋顶合批不能直接整批透明隐藏，否则会一次隐藏全城屋顶。

## 4. 内容、地图与流程分开维护

| 文件 | 作用 |
|---|---|
| `data/dialogues/lijiang_*.json` | 用户确定的逐句对话、动作旁白、已有立绘和院景 |
| `data/lijiang_city.json` | NPC锚点、名字、线索、半径、水渠与桥位 |
| `data/journeys.json` | 主线步骤和默认镜头参数 |
| `LijiangCity.gd` | 单站任务、交互与收尾；不把三线索逻辑塞入所有城市 |
| `CityWalkGuide.gd` | 可复用的物理地面采样和路线计算 |
| `LijiangMinimap.gd` | 小地图与目标选择；可按下一城市数据抽取复用 |
| `DialogueScene.gd` | 共用对话，支持独立场景与地图内叠层两种模式 |

地图内叠层对话通过 `configure_inline(id)` 配置。冻结玩家输入，保留地图画面；结束与退出分别发信号，地图决定是否记进度。对话进入院内时可切到已有背景。旧独立对话场景、选项动作和路由仍可运行。

## 5. 用独立标记，避免自由顺序变成隐藏顺序

三线索分别保存在 `clue/lijiang/silver`、`student`、`inn`。线索数由三个不同标记计算，不能每聊天一次就 `count += 1`。重复访谈可以重温，不重复发线索。主线标记为 `flow/lijiang/arrival`、`interviews`、`dongba_visit`、`glyph`、`farewell`。

完成对话后再保存标记；对话中途退出不保存“读到一半算完成”。交互同时检查平面距离、高差与视线，不允许隔墙、隔渠、隔楼层触发。任务指向与NPC位置一致，远处只引路，到位才显示 E。

## 6. 分清“小游戏通过”和“碎片已领取”

原有 `GameState.is_puzzle_solved()` 代表本站已完成；原接口在发碎片时也会解锁下一站。丽江新链路需要在收尾之后领奖，因此不能直接套用它来表示“两关刚通过”。

在丽江的 `glyph` 步骤配置 `defer_reward=true`，路由将参数传给真实小游戏。两关完成仅保存 `flow/lijiang/glyph`，不给碎片，不标记站点完成。`JourneyFlow.step_done()` 认识这个通过标记。阿东巴收尾结束后，地图核对三线索、核心对话和真实通过标记，再调用原有幂等的 `collect_fragment()`；由 GameState 自动完成丽江和解锁香格里拉。

其他城市、旧直接路由与独立内存试玩维持原奖励方式。已有丽江碎片的旧档直接显示完成，不要求重新问人。通关后关闭程序、离开或读档，都能恢复待核对状态。

## 7. 引导从物理生成，验收也要走物理

`CityWalkGuide` 使用0.6米采样格：射线确认落脚面，半径0.34米、高1.65米的胶囊确认角色空间。严格限制斜向穿角，在NPC实体外寻找最近落脚点；铺装权重1，其他地面3.5。路径同时供路面箭头、小地图使用，不另画一条可能穿墙的示意线。

自动测试不是把角色传到每个点就算可达。`LijiangChainTest` 实际注入 W 键、改变面向，让 CharacterBody3D 连续步行：出生点到银饰、银饰到小学生、小学生到客栈、客栈到东巴院，以及三座桥。小游戏用真实出牌点击与残页拖放提交。另测提前拜访、读一半退出、重复访谈、反向访谈顺序、暂停、存档、退出返回、延后领取与旧档。

headless只用于逻辑/物理检查；画面另以正常窗口渲染。实测项目默认Metal Forward+，兼容渲染器也检查过场景。对话长句使用已有可滚动文本框，必须检查截图中实际文字与按钮，不以编译成功代替排版检查。

## 复用到下一城的步骤

1. 查看模型来源、节点坐标与现有故事，列出实际NPC和终点。
2. 为本城建立独立点位数据与少量专用逻辑；先保持主线和碎片ID稳定。
3. 检查街道、桥梁、出生与NPC周围的角色空间，选择行走及镜头碰撞。
4. 配置默认镜头、任务目标、小地图、可达路线与交互视线。
5. 接逐句文本，定义“开始/中断/结束/重温”各自的进度变化。
6. 如需小游戏后再交付信物，沿用延后领取机制；不要提前标本站完成。
7. 连续实走所有必经路线，实做小游戏及收尾，再检查旧流程。
8. 冻结候选、计算指纹，在独立副本测试，记录日志和真实截图。

## 试玩反馈：操作与就近提示

丽江探索默认捕获鼠标，直接移动鼠标转视角，无需按住右键；Tab切换光标操作以点击任务清单、小地图、行囊和返回长卷。对话、暂停、奖励、离开城市和窗口失去焦点时释放光标。把Tab放在GUI之前的输入阶段，避免按钮焦点吃掉切换键。

金色箭头保留原物理可达路线，按1.3米间距从终点倒排，减少移动时整条路标跳动；只在角色移动超过0.75米或切换目标时重新寻路。到目标的可交互范围后收起路面箭头，用人物旁投影到屏幕的「E 对话」提示接替；隔墙、未到位和对话弹层期间不显示可交互提示。

对话将空格、Enter放在GUI之前处理：打字时补全，文字完整后继续；有分支时保留选择行为。提示同步写明「点击 / 空格补全文字」「点击 / 空格继续」。结束对话后要求松开空格再跳，避免最后一次空格连带角色跳跃。

旁白也显示写有「旁白」的姓名卡，正文从28放大至36。正文先固定可用宽度、再计算实际行高，让短句在正文区域居中，长句留在框内；不能用无限fit_content最小高度把整个框顶出屏幕。文本检查同时验证行高与屏幕边界。阿东巴核心对话正常完成后，保存步骤并延迟调用既有小游戏路由；中断不触发游戏，中途退出游戏仍回原地点。流程测试必须验证无需额外E输入即可进入。

## 当前边界

截至2026-10-11，丽江地图女主和四NPC已换为真实GLB人物，三个街头NPC有同阿东巴画风的新立绘；对话左NPC、右既有女主剪影，手机照片支持亮度与放大，初次完成后的再次对话为简短回应。没有新增可步行3D室内；模型使用轻量分件步行动作，尚无完整骨骼动作库。各批测试只证明对应候选和范围，不能据此宣称其他地图或整个五站已经完成。具体素材与证据见上述人物创作指南。

## 迁移时必须适配的代码限制

### 城市脚本和点位

不要让其他城市直接继承 `LijiangCity.gd` 再只换station_id。该类的STORY_PATH、`flow/lijiang/*`、`clue/lijiang/*`、三人计数、水车、河道、院门偏移和目标名仍包含丽江专用逻辑。迁移时使用本城标记及NPC列表，所有姓名、提示、“3/3”和前置条件一并适配。

丽江的出生偏移 `[3,0,-5]`、阿东巴院门偏移 `(0,0,1.6)` 和镜头数值只作参考。大理旧GLB的Empty轴向、普洱的行走碰撞数据各有专门处理，不能用丽江坐标假设覆盖。NPC、路线终点、地图标记与交互半径共同使用同一实际安全站位。

### 镜头碰撞和路网

当前CityScene只给丽江、普洱加载专用镜头碰撞。移植层4球形检查时，要同步生成本城camera_collision.res并接入加载条件；否则检测的层中没有本城建筑。烘焙器里的丽江节点筛选规则也不能原样用于另一城。使用BAKE_CITY只处理目标城市，先核对输出规则；普洱GLB烘焙主要输出镜头碰撞，行走仍来自map_data.json。

CityWalkGuide目前地面射线从Y=0.8到Y=-0.65，铺装面通过形状来源名Path_Flagstone识别。有山坡、码头、高台或不同材质名的地图必须适配范围和名称；不能将采样不到地面简单归因于NPC站错。

LijiangMinimap仍写死X=-29—29、Z=-20—22的投影、丽江标题和河道桥位。换城市要按本城bounds归一化；河道、桥、图例和点击目标规则一起修改。高差地图需要明确展示哪一层。地面箭头与小地图继续使用同一条物理路径。

### 延后领奖的逻辑与文案

JourneyFlow与PuzzleBase支持defer_reward=true；真实通关保存 `flow/<station>/<flow_step>`，不先发碎片、不标整站完成。收尾结束后核对前置状态，调用幂等的GameState.collect_fragment()。GameState.is_puzzle_solved()与本站奖励完成相关，不能直接当作收尾前的小游戏通过标记。

各小游戏拥有自己的_show_win_placeholder()，改基类不会自动改完结算UI。香格里拉知识页目前会显示“获得…已放入行囊”；大理与普洱也要检查自己的文案、按钮及完成接口。延后发奖时改成“整理完成／请师傅核对”，返回收尾；未领奖时不能仍声称碎片已入行囊。独立mock试玩、旧直接入口和未迁移城市保持原奖励方式。

当前每城仍按既有小游戏模块路由。多个小关优先在本城原模块内部组织，不凭flow新增多个puzzle条目就声称已经支持任意多个小游戏模块。

参考流程片段（需合并到本城配置，本城地图实现访谈和自动接续；对话ID是待替换占位）：

  {"id": "arrival", "type": "dialogue", "content": "your_city_arrival"},

### 自动接续和返回

核心对话正常完成时先保存本城步骤，再延迟调用CityAdapter.resume_story()。本城地图应提供city_context()，现有路由才能传递站点、位置、yaw、pitch和距离。转场阶段关闭玩家输入并释放光标。中断对话不进入游戏；中途退出游戏保留原地点，允许再找核心NPC开始。

小游戏完成后沿原路由返回，由本城地图检查“游戏通过、收尾未完成”，自动播放收尾。收尾中断保留游戏成果；已完成旧档直接显示完成，不重复开场或领奖。

### 操作与布局

姓名和E提示分工：姓名帮助认人，E表示现在可以交谈；未满足核心NPC条件时显示缺少什么，不给虚假的可启动提示。远处引路、近处提示，不能所有信息只放底栏。

Tab和对话空格在GUI前处理，防止保留的按钮焦点吞键；对话和弹层期间禁用探索输入，失焦和离开城市释放光标。正文先确定宽度，再测行高与位置，检查文本高度和屏幕边界。同步地图底栏、对话提示、暂停菜单controls_help()和玩家说明，避免仍写“右键拖动”或“核心对话后再按E”。
